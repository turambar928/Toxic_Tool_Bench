\section{Related Work}
\label{sec:related}

\paragraph{Tool use and agent evaluation.}
ReAct combines reasoning with actions, Toolformer learns when to call APIs, and PAL uses programs to carry out calculations \citep{yao2023react,schick2023toolformer,gao2023pal}. ToolBench, API-Bank, and Gorilla evaluate or train models to choose tools and form API calls \citep{qin2023toolllm,li2023apibank,patil2024gorilla}. AgentBench and WebArena extend evaluation to tasks that require several actions in interactive environments \citep{liu2023agentbench,zhou2023webarena}. ToxicBench studies what happens after a tool executes: whether the agent accepts a returned claim or checks it against other evidence.

DAComp evaluates repository-level data engineering and open-ended analysis, with human agreement and ranking-stability checks for its evaluator \citep{lei2025dacomp}. ToxicBench focuses on a complementary question: how changing a returned observation affects the agent's evidence use on the same underlying task.

\paragraph{Errors and recovery.}
\emph{Tools Fail} studies silent errors in calculators and embodied planning, including detection and recovery \citep{sun2024toolsfail}. ToolBench-X tests recoverable hazards such as output drift, execution failure, and conflicting sources \citep{tian2026toolbenchx}. PALADIN studies self-correction after tool failures, and Expected Recovery Regret measures recovery under execution noise \citep{vuddanti2025paladin,vuddanti2026err}. AgentAtlas separates task outcomes from decisions and trajectory quality; structural testing uses traces and assertions to inspect agent components \citep{mazaheri2026agentatlas,kohl2026structural}. AgentProp-Bench audits automatic judging, error propagation, and runtime checks \citep{gurram2026agentprop}. ToxicBench adds paired tabular tasks in which the source data stay fixed and the returned observation changes.

\paragraph{Poisoned instructions and evidence.}
Prompt injection can place hostile instructions in user input or retrieved content \citep{perez2022ignore,greshake2023indirect}. MCP-ITP attacks tool metadata, while TRUSTDESC builds tool descriptions from implementations \citep{li2026mcpitp,ye2026trustdesc}. AgentDojo and AgentCanary provide executable settings for testing agent attacks and defenses \citep{debenedetti2024agentdojo,li2026agentcanary}; AgentSentry targets indirect prompt injection during an agent run \citep{zhang2026agentsentry}. PoisonedRAG and SafeRAG study corrupted retrieval evidence \citep{zou2024poisonedrag,liang2025saferag}. PoisonArena and CPA-RAG further examine competing or covert attacks on retrieved content \citep{chen2025poisonarena,li2025cparag}. In a financial setting, manipulated tool data can also shift recommendations away from a user's risk profile \citep{wu2026agentdrift}. ToxicBench applies controlled numerical and semantic changes directly to returned data-tool observations. Table~\ref{tab:closest-work} compares these evaluation settings.

\paragraph{Data quality and evidence checks.}
Data-validation systems check schema constraints and data quality before downstream use \citep{schelter2018automating,breck2019data}. RADAR tests how models handle missing values, outliers, and inconsistencies in tables \citep{gu2025radar}. For retrieved evidence, SDAG limits attention across documents, RAGRank scores source credibility, and RAGShield checks numerical claims against a source registry \citep{dekel2026sdag,jia2025ragrank,patil2026ragshield}. ToxicBench keeps source tables available and tests whether an agent uses them to check a changed tool response.

\paragraph{Feedback and verification.}
Reflexion, Self-Refine, and MetaRAG use feedback or self-monitoring to revise answers \citep{shinn2023reflexion,madaan2023selfrefine,zhou2024metarag}. Co-Sight checks conflicts between structured facts, while Proof-of-Use trains agents to ground answers in retrieved evidence \citep{zhang2025cosight,ma2025pou}. ToolCritic provides feedback on specific tool-use errors \citep{hamad2025toolcritic}. Work on tool-use calibration and MICE links confidence estimates to tool decisions \citep{xuan2026confidence,subramani2025mice}; MIRROR evaluates whether models use self-knowledge to guide decisions \citep{wang2026mirror}. Our verification experiments compare ordinary second passes with prompts that ask for explicit checks, using the same route and token limits.
