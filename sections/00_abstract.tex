\begin{abstract}
Tool-augmented language agents are increasingly used for data analysis, where they query databases, execute Python code, retrieve documentation, and compose final analytical reports from tool observations. Existing reliability evaluations mainly study explicit tool failures such as crashes, timeouts, malformed outputs, or unavailable APIs. We argue that a more dangerous and under-explored failure mode is \emph{silent tool unreliability}: the tool returns a syntactically valid and apparently successful result, but the result is numerically corrupted, semantically biased, or adversarially contaminated.

We introduce \benchmarkname{}, a benchmark for measuring whether data agents blindly comply with unreliable tool outputs. \benchmarkname{} wraps ordinary data-analysis tools with controlled perturbations that preserve normal execution semantics, including numerical poisoning, label and schema inversion, stale metadata, and biased retrieval evidence. Our current instantiation contains 34 numerical tasks and 24 semantic/schema tasks over tabular data, evaluated with full framework adapters for LangGraph, smolagents, \texttt{data2mcp}, PandasAI, DA-Agent, and AutoGen across three model families where practical. The results expose a gap between tool use and tool trust: agents that solve clean tasks often copy poisoned values or corrupted labels into final answers. We evaluate clean-task performance, degradation under poisoning, blind compliance, anomaly detection, validation, and recovery. Finally, we evaluate \methodname{}, a lightweight guarded-verification wrapper that forms pre-tool expectations and independently validates suspicious observations. On \texttt{data2mcp}, \methodname{} reduces blind compliance to zero on both numerical and semantic/schema suites while substantially improving poisoned-task recovery.
\end{abstract}
