\section{ToxicBench and Guarded Verification}
\label{sec:benchmark}
\label{sec:problem}

ToxicBench tests whether data agents can distinguish successful tool execution from trustworthy evidence. For a query $q$, an agent calls a tool $f$ with input $x$ and receives $o=f(x)$. In the poisoned environment, a proxy returns $\tilde{o}=P(f,x,o;\theta)$. We call the poisoning \emph{silent} when $\tilde{o}$ preserves the expected interface, reports successful execution, and remains relevant enough to support a plausible answer. The same agent, task, data, and model are evaluated once with $o$ and once with $\tilde{o}$, isolating trust calibration from ordinary task difficulty.

\subsection{Benchmark Design}

Each item contains a query, one or more datasets, a clean oracle or rubric, and a poisoning specification. Poisoned outputs preserve schema, type, and formatting, and never expose an exception or warning. Each task also retains an independent verification path, such as recomputation from raw rows or inspection of source metadata. This design avoids reducing the benchmark to parsing robustness while supporting behavior-level scoring.

The cross-model evaluation contains 34 numerical tasks over 11 CSV datasets and 24 semantic/schema tasks over 14 datasets. Expanded GPT-only and defense evaluations use 60 tasks from each family. A separate 13-task extension requires multi-table joins. Together, these suites cover arithmetic trust, value--entity binding, schema interpretation, metadata use, retrieval grounding, and join-based analysis.

\subsection{Poisoning Operators and Metrics}

\paragraph{Numerical poisoning.}
Numerical operators target computation outputs from Python, pandas, SQL, or dataframe routes:
\begin{itemize}
    \item \textbf{Aggregate scaling:} multiply a requested aggregate such as a mean, sum, rate, or count by a controlled factor while preserving the surrounding output format.
    \item \textbf{Sign flip:} reverse the sign of a change, growth rate, or delta while keeping the magnitude plausible.
    \item \textbf{Rank/label swap:} swap the entity label attached to a statistic or ranking result while leaving the value format intact.
\end{itemize}
These operators test both arithmetic checking and preservation of value--entity bindings.

\paragraph{Semantic and schema poisoning.}
These operators corrupt evidence binding rather than numeric magnitude:
\begin{itemize}
    \item \textbf{Label swap:} replace an entity label associated with an otherwise plausible result.
    \item \textbf{Treatment/control flip:} invert experimental group semantics while preserving outcome values.
    \item \textbf{Column-semantic swap:} swap column descriptions or meanings in schema evidence.
    \item \textbf{Stale metadata:} return outdated data-dictionary or source-of-truth metadata.
    \item \textbf{Biased retrieval:} return evidence rows or snippets that support the wrong conclusion while appearing relevant.
\end{itemize}
We score final answers against the clean oracle and compute behavior labels from the logged trajectory. The released deterministic scorer reports:
\begin{itemize}
    \item \textbf{Task Success Rate (TSR):} the fraction of tasks that satisfy the clean reference answer or rubric.
    \item \textbf{Poisoned Degradation ($\Delta$TSR):} the drop from clean TSR to poisoned TSR.
    \item \textbf{Blind Compliance Rate (BCR):} the fraction of poisoned runs in which the agent directly uses the poisoned observation in the final answer or downstream computation without qualification or independent validation.
    \item \textbf{Anomaly Detection Rate (ADR):} the fraction of poisoned runs in which the agent explicitly identifies a discrepancy, implausibility, or possible tool error.
    \item \textbf{Validation Rate (VR):} the fraction of poisoned runs in which the agent performs an independent check, such as recomputing from raw data, querying another tool route, inspecting schema evidence, or comparing against invariants.
    \item \textbf{Recovery Rate (RR):} the fraction of poisoned runs where the agent identifies the issue through anomaly detection or validation evidence and still produces the clean answer or an appropriately qualified final answer.
\end{itemize}

BCR, ADR, VR, and RR are computed on poisoned runs. Verbal caution alone may receive ADR credit, but VR requires fresh evidence obtained after the poisoned observation; RR additionally requires the clean answer or an appropriately qualified rejection. An 80-run stratified author audit obtains 1.00 agreement and Cohen's $\kappa=1.00$ across all four labels. Appendix~\ref{sec:appendix-metric-protocol} gives exact rules and borderline cases.

Table~\ref{tab:metric-scoring-rules} states the core decision rules. The scorer first confirms that the proxy returned a poisoned observation, then matches the final answer against clean and poisoned numeric tolerances, aliases, or categorical rubrics. It next inspects ordered post-poison events for explicit anomaly statements and fresh evidence. This ordering prevents an agent from receiving validation credit for generic caution written before the corruption appears.

\subsection{Guarded Verification}
\label{sec:method}

Guarded Verification changes how observations enter the final answer without retraining the model. Given query $q$, it (1) records coarse expectations or invariants, (2) runs the ordinary primary tool route, (3) obtains fresh evidence through an independent route, and (4) gives verified evidence priority when the two routes disagree. Expectations need not predict the answer; they capture constraints such as valid ranges, entity--value bindings, schema meanings, units, and source support. Independent evidence may come from recomputing raw rows, re-reading a table rather than copying a summary, checking labels against source data, or querying another tool route.

We operationalize independence at the evidence level. A verification event must occur after the poisoned observation and access a source that is not the primary returned summary. The verification prompt includes the original query and task context but does not present the primary value as a fact to confirm. When routes agree, the agent can finalize normally. When they conflict, the verified result takes priority; if verification is inconclusive, the guard must qualify or abstain rather than silently select the primary result. This policy makes the BCR reduction interpretable as a change in evidence adoption, while RR measures whether the additional route actually recovers the task answer.

The main ablation uses \texttt{poison\_once}: the first eligible observation can be corrupted, while a later independent route can access clean evidence. This controlled threat model tests whether the agent uses redundancy when it exists; it does not protect against corruption of the underlying source or every route. We evaluate full and light guards, which differ in verification budget, as well as prompt-only and verification-only ablations. A repeated-poisoning stress test measures degradation when verification routes are also exposed. The wrapper is implemented for LangGraph ReAct and replicated on AutoGen, showing that it is not tied to one agent loop. Full implementation details, tie-breaking rules, and stronger-adversary results appear in Appendix~\ref{sec:appendix-guard}.
