\section{Introduction}
\label{sec:introduction}

Large language model (LLM) agents increasingly solve complex tasks by delegating computation, retrieval, and environment interaction to external tools \citep{schick2023toolformer,yao2023react,qin2023toolllm}. In data-analysis settings, this delegation is essential: agents inspect schemas, run SQL queries, execute Python notebooks, call vector databases, and synthesize reports from tool observations. As a result, an agent's final answer is no longer determined only by its parametric knowledge or instruction following ability, but also by how it interprets and audits external observations.

Most existing evaluations of tool-augmented agents focus on whether the agent can select the correct tool, invoke it with valid arguments, recover from explicit execution errors, or complete a task with tool access. These evaluations leave a critical reliability gap. In deployed systems, tools may return normal-looking but unreliable results: a data pipeline may silently apply the wrong unit conversion, a retrieval index may surface stale or biased rows, a preprocessing component may swap column semantics, or user-controlled data may contain instructions that look like metadata. Such failures do not raise exceptions. They return a successful observation that the agent must decide whether to trust.

We call this setting \emph{implicit tool poisoning}. Unlike tool crashes or malformed API responses, implicit poisoning preserves the operational interface of the tool. The agent receives a syntactically valid output and must rely on consistency checks, task context, commonsense constraints, or secondary validation to notice the discrepancy. This setting is especially important for data agents because many analytical conclusions are plausible-looking even when they are wrong. A corrupted mean, a biased retrieval result, or a poisoned metadata field can be directly copied into a final business recommendation.

This paper asks a simple question: when a trusted tool silently lies, do data agents notice? To answer it, we propose \benchmarkname{}, a benchmark that injects controlled silent failures into data-analysis environments while keeping tool calls successful. We evaluate cross-agent and cross-model behavior on a 34-task numerical suite and a 24-task semantic/schema suite, then run an expanded 120-task \texttt{data2mcp} defense ablation with 60 numerical and 60 semantic/schema tasks. The numerical tasks corrupt aggregates, signs, and entity-statistic bindings. The semantic/schema tasks corrupt treatment/control labels, column meanings, stale data-dictionary entries, and retrieved evidence snippets. We evaluate agents not only by final task success, but also by whether they exhibit blind compliance, verbalized anomaly detection, corrective validation, and robust recovery.

We also evaluate a lightweight defense direction, \methodname{}, that adds a metacognitive guard around the agent loop. Before tool execution, the agent produces a coarse expectation or invariant for the requested observation. After tool execution, the guard performs independent validation before finalizing. In the expanded \texttt{data2mcp} ablation, this guarded verification reduces observed blind compliance from 0.41 to 0.00 and improves poisoned-task success from 0.47 to 0.84 over 120 tasks. The result suggests that the failure is not inevitable: agents can become more robust when tool observations are treated as evidence to audit rather than facts to copy.

Our intended contributions are:
\begin{itemize}
    \item We formulate silent tool unreliability as an agent evaluation problem distinct from explicit tool failure and ordinary hallucination.
    \item We introduce \benchmarkname{}, a benchmark for testing blind compliance to poisoned but successful tool outputs in data-analysis agents, with numerical and semantic/schema task families.
    \item We define behavioral metrics that separate clean capability from trust calibration, including blind compliance rate, anomaly detection rate, validation rate, and poisoned-task degradation.
    \item We evaluate complete framework adapters, showing that high clean-task performance often coexists with blind compliance under silent poisoning.
    \item We evaluate \methodname{}, a plug-and-play guarded-verification wrapper, showing that it can eliminate observed blind compliance for \texttt{data2mcp} while improving poisoned-task recovery.
\end{itemize}
