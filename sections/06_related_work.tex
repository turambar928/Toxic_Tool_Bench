\section{Related Work}
\label{sec:related}

\paragraph{Tool-augmented language agents.}
Tool-augmented language models use external APIs, retrieval systems, program interpreters, and environment actions to solve tasks beyond ordinary text generation. Prior work studies how models learn to call tools, interleave reasoning and acting, or use programs as intermediate computation \citep{schick2023toolformer,yao2023react,gao2023pal}. Tool-use benchmarks and API corpora such as ToolLLM/ToolBench, API-Bank, and Gorilla evaluate whether models can select tools, construct valid arguments, and complete tool-mediated tasks \citep{qin2023toolllm,li2023apibank,patil2024gorilla}. ToxicBench studies a complementary dimension: after a tool call succeeds and returns a syntactically valid observation, can the agent decide whether that observation deserves trust?

\paragraph{Agent reliability and error recovery.}
General agent benchmarks evaluate long-horizon planning, interaction with web or software environments, and recovery from invalid actions or incomplete context \citep{liu2023agentbench,zhou2023webarena}. Recent trajectory-centered evaluations argue that agent reliability should be decomposed beyond final success: AgentAtlas proposes control-decision and trajectory-failure taxonomies, while ERR--ES relates recovery quality to efficiency under execution noise \citep{mazaheri2026agentatlas,vuddanti2026err}. Structural testing work similarly argues for trace-level assertions over agent executions rather than only final-answer checks \citep{kohl2026structural}. PALADIN trains agents to recover from explicit tool failures such as timeouts and API exceptions \citep{vuddanti2025paladin}. These settings expose important failures in task decomposition, state tracking, and environment interaction. Silent tool poisoning differs because the failure is not an explicit invalid action, exception, or missing observation. The agent receives a normal-looking result at the expected interface, so the challenge is semantic skepticism toward plausible evidence rather than syntactic recovery from an error signal.

\paragraph{Prompt injection and data poisoning.}
Data-embedded instruction risks in ToxicBench are related to prompt injection and indirect prompt injection, where untrusted retrieved or tool-provided content can influence downstream model behavior \citep{perez2022ignore,greshake2023indirect}. Our attack surface is broader than explicit instruction strings: poisoned observations may be corrupted aggregates, swapped labels, stale metadata, or biased retrieved evidence. The desired behavior is therefore not merely refusal. A robust data agent should continue the analysis while treating tool observations as evidence to validate rather than commands or facts to copy.

\paragraph{Tool-description and agent-security poisoning.}
MCP-ITP and TRUSTDESC study tool poisoning at the description and registration layer, where misleading or malicious tool metadata biases tool selection or induces unsafe tool use \citep{li2026mcpitp,ye2026trustdesc}. AgentCanary provides a broader agent-security framework with an Entry--Impact taxonomy and trajectory-grounded security metrics for real executable environments \citep{li2026agentcanary}. AgentDrift studies unsafe recommendation drift under corrupted tool outputs, showing that plausible external outputs can shift agent behavior even without visible execution errors \citep{wu2026agentdrift}. AgentSentry addresses indirect prompt injection with temporal causal diagnostics and context purification around agent boundaries \citep{zhang2026agentsentry}. These works are complementary. ToxicBench narrows the setting to data-analysis tools and standardizes paired clean/poisoned tasks, poisoning operators, and behavior metrics for blind compliance and recovery. AgentSentry-style causal diagnostics could serve as stronger future guard triggers, while ToxicBench provides a controlled data-agent testbed for such defenses.

\paragraph{RAG poisoning and evidence security.}
Recent RAG security benchmarks and attacks study how manipulated retrieved documents can steer generation. SafeRAG evaluates injected noise, conflict, toxicity, and denial-of-service risks across the RAG pipeline \citep{liang2025saferag}. PoisonArena formalizes multi-attacker retrieval poisoning and shows that single-attacker attack-success metrics can miss competitive effects \citep{chen2025poisonarena}. CPA-RAG studies covert black-box poisoning texts that manipulate retrieval toward target answers \citep{li2025cparag}. These works share our concern with plausible external evidence, but they primarily target corpus or retrieval-context corruption. ToxicBench instead targets the agent--tool observation boundary in data analysis, where the corrupted object may be a dataframe result, schema lookup, computed aggregate, or retrieved evidence snippet. This makes trust calibration observable at the trajectory level: the agent can copy, question, validate, or recover from a successful-looking tool observation.

\paragraph{Evidence-integration defenses.}
Defenses for poisoned evidence include retrieval filtering, provenance checks, and mechanisms that constrain how evidence is integrated. SDAG, for example, uses sparse document attention to prevent harmful cross-document interactions in poisoned RAG contexts \citep{dekel2026sdag}. RAGRank uses source-credibility scoring to demote poisoned retrieval evidence in cyber-threat intelligence pipelines \citep{jia2025ragrank}. These defenses are orthogonal to Guarded Verification: SDAG and RAGRank constrain which retrieved documents receive authority, while our guard constrains answer selection by requiring an independent evidence route before adopting a tool observation. Provenance and attention-based defenses are promising complements for retrieval-style tasks in ToxicBench, especially when the verification route itself may be exposed to poisoning.

\paragraph{Runtime assurance and tool-output sanitization.}
Another line of defenses treats the agent loop as a runtime system with policies over tool calls, outputs, and final actions. Contract-based gates such as ToolGate-style postconditions, solver-aided policy checking, and runtime interceptors can prevent unsafe actions or reject outputs that violate formal constraints. Tool-result parsing and sanitization for indirect prompt injection similarly strips or isolates instruction-like content before it reaches the model. ToxicBench is complementary to these defenses. Our poisoned observations are often ordinary-looking numbers, labels, schema meanings, or evidence snippets rather than explicit instructions, so syntactic sanitization alone is not enough. Likewise, a postcondition can catch a count outside a legal range, but it may not catch a plausible group-label swap unless the contract encodes the relevant source-row binding. Guarded Verification is closer to a content-level evidence check after successful tool execution. A full-stack defense could combine policy gates for action safety, parsing and provenance filters for untrusted text, and independent verification for numerical and semantic evidence.

\paragraph{Data quality and schema reliability.}
Data-analysis agents depend on schemas, data dictionaries, documentation, and retrieved evidence to decide which columns and rows are relevant. Data validation and data-quality systems check constraints such as types, missing values, distribution shifts, and schema expectations before data enters downstream workflows \citep{schelter2018automating,breck2019data}. RADAR benchmarks language models on imperfect tabular data with artifacts such as missing values, outliers, and logical inconsistencies \citep{gu2025radar}. ToxicBench moves this reliability question into the agent loop and changes the locus of corruption. Instead of only asking whether a model can reason over an imperfect table, we ask whether an agent over-trusts a successful tool observation whose content has been silently changed, such as swapped column semantics, stale source-of-truth fields, or inverted treatment labels. These settings are complementary: RADAR measures data-aware reasoning under table artifacts, while ToxicBench measures trust calibration at the tool-observation boundary.

\paragraph{Uncertainty, calibration, and self-verification.}
Self-checking and verification methods ask models to critique, revise, or validate their own outputs \citep{shinn2023reflexion,madaan2023selfrefine}. Metacognitive RAG systems such as MetaRAG add monitoring, evaluation, and planning around retrieval for multi-hop QA \citep{zhou2024metarag}. Co-Sight proposes conflict-aware meta-verification over structured facts, and Proof-of-Use uses evidence-use contracts to reduce tool-call hacking in research agents \citep{zhang2025cosight,ma2025pou}. These systems share our view that evidence should be audited before it controls final generation, but ToxicBench focuses on the data-agent observation boundary and measures whether agents copy, question, validate, or recover from silently corrupted observations. Calibration work for tool-use agents is also relevant because confidence can determine when an agent should call a risky tool, abstain, or verify. Recent work on tool-agent miscalibration finds that evidence tools can induce overconfidence while verification tools can improve calibration \citep{xuan2026confidence}. MIRROR argues that external metacognitive scaffolding can reduce confident failures more effectively than simply providing models with calibration scores \citep{wang2026mirror}. MICE learns model-internal confidence estimators for tool-calling agents and evaluates confidence-gated tool use through expected tool-calling utility \citep{subramani2025mice}. AgentProp-Bench further highlights judge reliability and propagation effects in tool-using agents, reinforcing the need to calibrate trajectory-level labels rather than treating automated judges as infallible \citep{gurram2026agentprop}. Guarded Verification is complementary: rather than estimating confidence directly, it changes the loop so that final answers must be grounded in independently checked evidence. A natural extension is selective guarded verification, where calibrated uncertainty, route disagreement, or provenance risk triggers verification only for high-risk observations.
