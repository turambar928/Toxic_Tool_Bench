\section{Conclusion and Limitations}
\label{sec:discussion}

ToxicBench measures how data agents respond when a successful tool call returns wrong evidence. Its paired tasks separate changes to the returned observation from changes to source data. The verification experiments distinguish another attempt at the task from an explicit request to check an earlier answer. Later clean observations are common under one-shot poisoning; repeated poisoning exposes cases in which agents check evidence and still adopt the wrong conclusion, a behavior confirmed on four adjudicated holdout trajectories. Together, the task pairs, trace analysis, and human comparisons provide a common setting for testing how agents select and use evidence.

The core benchmark uses small synthetic tables and controlled observation changes, not deployment-frequency sampling. Separate field-bound controls on three public tables support a local evidence-condition effect, not deployment robustness or a causal decomposition of historical gains. Their seeded calls and structured answers differ from the original adapters. Delivery auditing flags historical off-target edits; full-target validity is established only for the new explicit query bindings, not arbitrary outputs. Independent human scorer validation and affected-label re-review remain pending. Intervals condition on selected tasks and sources, not label uncertainty or comprehensive API variation. Production workflows and separate evidence sources remain outside the demonstrated scope.
