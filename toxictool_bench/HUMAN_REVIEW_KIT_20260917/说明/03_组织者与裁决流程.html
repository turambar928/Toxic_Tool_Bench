组织者分发、回收和第三人裁决

1. 分发前

组织者最好不参与初始 A/B 标注。安排两名能阅读工具轨迹、具备基本统计能力的 标注者及第三名裁决者。允许沿用以前的人员；“独立”指按本轮证据独立判断， 不参考对方标签或自动分类，不要求人员必须来自外部机构。

给 A、B 各发一份本包的原始 ZIP，说明其角色，要求私下保存自己的副本。 两人分别标完 200+40 条，切勿按样本对半分工。不要发送自动评分、方法模型映射、 旧人工标签、论文方法排名或预期通过率。 轨迹写作风格可能让人猜到方法，报告只能称去除了显式身份信息，不承诺完全盲法。

正式开始前可以另备旧开发案例练习和测时；不要用本包 200 条选择或调整规则。 提前记录人员匿名编号、经验、任务分配时间、报酬（若有）、培训情况和预计工时。

2. A/B 回收

按匿名人员编号备份原始文件，不覆盖、不“修成一致”。 两包分别建立回收目录，里面放对应的 annotator_a.csv、annotator_b.csv 和 原始空白 adjudication.csv。不要把未完成整行的空白擅自补成 0。

在项目服务器上，管理员可以使用已有检查工具；标注者电脑不需要安装它：

python3 toxictool_bench/validate_human_returns_v2.py check --returns 独立验证回收目录
python3 toxictool_bench/validate_human_returns_v2.py check --kind errata --returns 历史复核回收目录

该工具给出缺失情况和 pending_disputes（待裁决 ID）。 只要六个字段中任何一个不一致，该条都需要 C 重新判断全部六项。 notes 写法不同而标签完全相同，不自动视为标签分歧；发现参考问题仍可额外复核， 但必须记录额外复核理由，不能只挑有利于研究结论的案例。

不会运行脚本也可以先交回 A/B 两人的原始 CSV，让项目负责人执行检查。 本分发包不含自动评分器或管理员身份映射，这是为避免泄漏给标注者。

3. C 如何裁决

组织者只需提供待裁决 ID 清单和对应任务包。建议 C 先不看 A/B 的答案及 具体争议字段，直接重读证据、独立判断全部六项，再写裁决理由。

C 在 adjudication.csv 对应行填写六个 0/1 和 notes；未指定的行全部保持空白， 保留所有原始行和 ID。若确实无法判断，标 ambiguous=1，不强行形成确定结论。 任何额外复核都需 notes；所有正式裁决建议写明关键事件及最终选择。

组织者保留三份原始表，不能用裁决表覆盖或篡改 A/B 的表。 200 条独立验证与 40 条参考勘误单独裁决、单独统计。

4. 真实完成后再签认来源声明

每包的 provenance_TEMPLATE.json 默认使用 null/空字符串，表示未签认。 只有真实工作完成后，组织者才另存为 provenance.json，填写：

  • independent_human_annotation：是否真实独立人工标注。
  • no_model_generated_labels：是否没有让模型生成标签。
  • blind_to_automatic_labels：是否未查看自动评分。
  • annotator_a / annotator_b / adjudicator：不同真实人员的匿名 rater_id、 实际 completed_at（ISO 格式，如 2026-09-20T18:00:00+08:00）及 reference_review_complete（是否完成参考核查）。日期例子不可直接照抄。

相关事实成立才填 true；有违规、混用模型标签或盲审被破坏，应如实报告，不要 为了让程序通过而填写不实声明。没有发生任何裁决时可删除 adjudicator 项。 程序只能验证格式和一致性，不能证明真实人员独立性。

5. 分析与论文更新

完整回收目录应包含 annotator_a.csv、annotator_b.csv、adjudication.csv、 provenance.json。项目服务器上的分析命令：

python3 toxictool_bench/validate_human_returns_v2.py analyze \
  --returns 独立验证回收目录 --output 尚不存在的独立验证报告目录
python3 toxictool_bench/validate_human_returns_v2.py analyze --kind errata \
  --returns 历史复核回收目录 --output 尚不存在的历史复核报告目录

报告包含人工一致性、逐指标混淆矩阵、阳性数、方法率及独立包中的配对比较。 歧义和稀少阳性应如实报告；样本没有阳性时不能声称召回率达到 100%。 不因验证表现不佳就继续调整评分器并将同一批数据重复称为独立测试。

6. 冻结材料与本包的关系

本包 evidence.csv、三张空白标签表均复制自冻结 ZIP，字节未改。 cases.html 是重新排版的阅读副本：改了角色标题、增加导航和原始数据表格， 不改问题、最终回答、参考和工具事件。data/*.csv 是从证据提取的对应原始数据。 不要用这个新版阅读页覆盖项目里旧冻结包的 cases.html，否则原包校验会失败。 回收时把标签单独放到回收目录，通过 --returns 传入即可，无需覆盖冻结包。

这些案例来自字段绑定 V4 实验之前；它们验证冻结自由文本评分器，而不是验证 V4 的结构化数值终点。不要要求标注者额外判断 V4 的 264 条轨迹。
