Tool-augmented language agents are increasingly used for data analysis, where they query databases, execute code, retrieve documentation, and write reports from tool observations. Most reliability evaluations focus on visible failures such as crashes, timeouts, malformed outputs, or unavailable APIs. We study a less visible failure mode: the tool call succeeds and returns a well-formed, relevant observation, but the content is incorrect.

We introduce ToxicBench, a benchmark for measuring whether data agents blindly comply with such silent tool poisoning. ToxicBench wraps ordinary data-analysis tools with controlled perturbations that preserve normal execution, including corrupted numerical results, swapped labels and schema meanings, stale metadata, and biased retrieval evidence. We evaluate an expanded 120-instance suite covering numerical and semantic/schema data-analysis tasks, together with a smaller cross-model suite of 34 numerical and 24 semantic/schema instances using full framework adapters for LangGraph, smolagents, PandasAI, DA-Agent, and AutoGen where feasible. The results show a consistent gap between tool use and tool trust: agents that solve clean tasks often copy poisoned values or corrupted labels into final answers. We report both broad poisoned-answer adoption and the narrower blind-compliance rate, which excludes runs that perform qualifying validation. Finally, we use Guarded Verification as a controlled protocol for measuring the value of additional evidence collection and evidence gating. In a leakage-free 120-instance LangGraph ReAct ablation with a matched-compute control, an unguarded second pass explains most of the improvement, while the generic guard removes the residual observed blind compliance under \texttt{poison\_once}. A full repeated-poison stress test shows that recovery degrades and blind compliance can return when verification observations are also corrupted.
