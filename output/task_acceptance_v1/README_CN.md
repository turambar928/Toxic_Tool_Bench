# 逐任务可执行验收 V1

这是一项**不调用模型 API**的确定性验收，不使用 GPT、Claude、Qwen 或 LLM 裁判，也不生成或改写人工标签。验收代码由 AI 辅助实现并经测试核对；这不应被描述为新的人工盲审。

## 结果概览

范围是 58 个保留数值任务、60 个语义/字段任务、13 个多表任务，共 131 题。原有两个分母含糊任务继续排除，并列在协议中；没有因本轮结果新增排除。每题执行一次投毒、持续投毒 p=1 两种条件，各调用初始工具、相同工具重算、原始数据路线，共 262 个组合、786 次工具调用。

| 任务集 | 题数 | 答案/规格一致 | 无歧义且改变目标结论的投毒 | 一次投毒后的原始数据恢复 | 持续投毒后的原始数据恢复 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 数值 | 58 | 58 | 48 | 48/48 | 48/48 |
| 语义/字段 | 60 | 60 | 60 | 60/60 | 60/60 |
| 多表 | 13 | 13 | 11 | 11/11 | 2/11 |
| 合计 | 131 | 131 | 119 | 119/119 | 110/119 |

恢复两列只以“接口无歧义且目标结论被改变”的任务为分母。两种条件的首次投毒检查一致。所有源文件及冻结输入哈希均保持不变。

全体 131 题在一次投毒后的预设原始数据路线都能给出正确答案，但不能把其中 10 个未暴露任务也记为“从投毒中恢复”。另外 2 个表名键冲突任务不计入有效目标投毒的恢复分母。

## 验收如何运行

1. **从源数据求答案。** `task_acceptance_specs.py` 根据数据集和问题定义公式、筛选、连接、字段角色或证据选择规则；不读取任务 oracle、投毒值、方法名或 task ID 来生成答案。标准库与 pandas 分别计算；之后才与现有评分参考比较。原有参考勘误只用于比较，绝不进入注入器配置。
2. **实际调用当前工具环境。** 没有人工拼出含 oracle 的假工具答案。数值/排序查询通过 `DataToolEnv.python_exec` 执行 pandas 计算，统一保留四位小数；预览任务实际调用 `preview(rows=20)`。20 行上限足以覆盖这些小表。没有为不同任务按 oracle 改变显示精度。
3. **执行真实返回值注入。** 使用未修改的 `poisoners.py` 和原始任务投毒目标。只在内存中切换声明的一次/持续投毒策略和 p=1，不覆盖任务文件。保留每次调用的参数、干净返回、实际返回和暴露标记。
4. **检查目标，不只检查文本是否变化。** 数值/排序检查明确的答案字段；字典/检索按返回行重新选择；schema 检查事先指定语义角色的列位置是否被改绑；表发现检查表名到字段的映射是否唯一。重复 JSON 键视为无歧义映射检查失败，不把它默认为合格投毒。
5. **执行恢复路线。** 先重复同一计算，再读取原始数据：单表 Python 计算任务使用另一个 preview 工具；预览和多表任务通过 Python 读取源行，再以标准库重新计算。路线是按工具边界预先指定的，不是 agent 自主发现的路线，不声称对攻击信息盲化。
6. **检查文件未变。** 每个组合比较源文件前后哈希，最终再次核对脚本、所有源数据、任务和历史参考审计的输入哈希。

## “131 个一致”具体是什么意思

检查包括：78 个算术/排序实例、15 个字典选择、15 个检索证据选择、2 个表发现查询和 21 个显式 schema 角色绑定。标准库和 pandas 共享同一问题解释和公式，只是计算实现分开。

因此，21 个 schema 角色检查不能被说成“独立语义标注验证”；它们证明指定列存在、绑定可检查、投毒位置和源数据恢复路径可执行。其他结果也不是双盲任务审查，不证明模板语义独立或所有自然语言解释都唯一。

## 保留的例外

### 10 个数值任务在固定显示格式下未触发投毒

原注入目标与实际复算结果不满足当前注入器的精确匹配条件。7 个与已有参考勘误有关；另 3 个在评分容差内，但并不与注入器目标精确相同。

任务 ID：

```text
num_iclr2027_ad_conversion_035
num_iclr2027_ad_ctr_036
num_iclr2027_ad_roas_037
num_iclr2027_inventory_return_041
num_iclr2027_inventory_units_per_order_043
num_iclr2027_clinic_recovery_047
num_iclr2027_repeat_053
num_iclr2027_repeat_054
num_iclr2027_repeat_055
num_iclr2027_repeat_059
```

这不等于“10 个新参考答案错误”，也不证明历史 agent 的其他格式一定不暴露。验收没有偷偷改用历史 oracle 生成初始答案以促成投毒。

### 2 个表发现预览产生重复表名键

`real_multi_preview_customers_001`、`real_multi_preview_support_002` 的字符串替换使维表名称与事实表名称相同，返回的表清单出现重复键。标准宽松 JSON 解析可能接受这样的字符串，但无法提供唯一的表名映射；本验收记录为接口检查失败、目标判定未解析。

### 持续投毒下 9 个多表恢复路线失败

原始行通过 Python 返回时，标签替换仍会命中恢复证据。因此它们不满足这条预设路线在持续投毒下的恢复条件。它不证明所有替代路线均不可恢复，更不是新测得的 agent 失败率。

## 文件和复现

- `protocol.json`：执行前写入的规则、全部任务配方、条件、排除项、输入哈希。写协议前已做开发测试，不能宣称这是未见结果的科学预注册。
- `cases/*.json`：每题参考比较、各阶段判定、源哈希和完整工具事件。
- `summary.csv` / `summary.json`：按任务集、投毒条件汇总的计数。
- `completion_manifest.json`：执行完成时的机器产物哈希。本说明文档在结果完成后添加，不属于该清单。
- 代码：`toxictool_bench/run_task_acceptance.py`、`task_acceptance_specs.py`。
- 回归测试：`toxictool_bench/tests/test_task_acceptance.py`，包括禁用网络、错误参考、遗漏并列答案、源数据扰动、非暴露分母、重复键及产物完整性检查。

在仓库根目录复现，输出目录必须是新目录：

```bash
python3 toxictool_bench/run_task_acceptance.py --output output/task_acceptance_recheck
python3 -m pytest toxictool_bench/tests/test_task_acceptance.py -q
```

不需要 `api` 文件或模型密钥。脚本拒绝覆盖既有运行目录。不要修改本轮例外任务、历史评分器或人工标签后，仍称其为同一冻结验收。

论文位置：正文 §3.1 概括覆盖，附录 A 的 `tab:task-acceptance` 给出三类任务的结果。主实验方法比较、评分器及人工结论未改变。本轮结果支持固定路线的可执行性，不追溯认证历史全部投毒事件，也不代表生产环境或多源独立验证。

接口范围是 `DataToolEnv` 参考环境与当前注入器，不是所有框架 adapter 的端到端验收。最终另在新目录重跑了一遍，机器产物的全部哈希与正式运行完全一致；完整测试为 201 项通过。官方模板 PDF 总计 27 页，正文仍为 9 页，验收表为第 15 页的 Table 5。
