\section{Introduction}
\label{sec:introduction}

Large language model (LLM) agents increasingly solve complex tasks by delegating computation, retrieval, and environment interaction to external tools \citep{schick2023toolformer,yao2023react,qin2023toolllm}. In data analysis, this delegation is central to the workflow: agents inspect schemas, run SQL queries, execute Python code, call vector databases, and synthesize reports from tool observations. The quality of the final answer therefore depends not only on the model's reasoning ability, but also on how the agent interprets evidence returned by tools.

Most existing evaluations of tool-augmented agents focus on tool selection, argument construction, recovery from explicit execution errors, or final task completion with tool access. These settings are important, but they leave a reliability gap. In deployed data systems, tools may return normal-looking but unreliable results: a data pipeline may apply the wrong unit conversion, a retrieval index may surface stale rows, a preprocessing step may swap column meanings, or user-controlled data may contain text that resembles metadata. These failures do not necessarily raise exceptions. They appear as successful observations, and the agent must decide whether to trust them.

We call this setting \emph{silent tool poisoning}. Unlike tool crashes or malformed API responses, silent poisoning preserves the tool interface. The agent receives a syntactically valid output and must use task context, consistency checks, or secondary validation to notice that the content is unreliable. This setting is especially important for data agents because many analytical claims remain plausible even when they are wrong. A corrupted mean, a biased retrieval result, or a stale metadata field can be copied directly into a final recommendation.

This paper asks: when a tool silently returns false evidence, do data agents notice? We propose ToxicBench, a benchmark that injects controlled silent failures into data-analysis environments while keeping tool calls successful. We evaluate cross-agent and cross-model behavior on a 34-task numerical suite and a 24-task semantic/schema suite, run a GPT-only expanded cross-agent evaluation on 120 tasks, and run a 120-task LangGraph ReAct defense ablation. The numerical tasks corrupt aggregates, signs, ratios, and entity-statistic bindings. The semantic/schema tasks corrupt treatment/control labels, column meanings, stale data-dictionary entries, and retrieved evidence snippets. We evaluate agents not only by final task success, but also by whether they copy poisoned observations, flag anomalies, validate independently, and recover the clean answer.

We also evaluate a lightweight defense, Guarded Verification, that changes how tool observations enter the final answer. Before tool execution, the agent writes coarse expectations or invariants for the requested observation. After tool execution, the guard performs an independent validation route before finalizing. In the expanded LangGraph ReAct ablation, Guarded Verification reduces observed blind compliance from 0.30 to 0.00 and improves poisoned-task success from 0.62 to 0.93 over 120 tasks. This suggests that blind compliance is not only a model limitation: it can be reduced by changing the agent loop so that successful tool outputs are treated as evidence to check, not facts to copy.

Our contributions are:
\begin{itemize}
    \item We formulate silent tool poisoning as an agent evaluation problem distinct from explicit tool failure and ordinary hallucination.
    \item We introduce ToxicBench, a benchmark for testing blind compliance to poisoned but successful tool outputs in data-analysis agents, with numerical and semantic/schema task families.
    \item We define behavioral metrics that separate clean capability from trust calibration, including blind compliance, anomaly detection, validation, recovery, and poisoned-task degradation.
    \item We evaluate complete framework adapters, showing that high clean-task performance often coexists with blind compliance under silent poisoning.
    \item We evaluate Guarded Verification, a wrapper that reduces observed blind compliance to zero for LangGraph ReAct in our expanded ablation while improving poisoned-task recovery.
\end{itemize}
