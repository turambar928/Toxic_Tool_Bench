\section{Introduction}
\label{sec:introduction}

Large language model (LLM) agents often solve complex tasks by using external tools for computing, retrieval, and interaction \citep{schick2023toolformer,yao2023react,qin2023toolllm}. In data analysis, agents rely on tools to inspect schemas, run SQL, execute Python, query vector databases, and write reports from tool outputs. So the final answer depends on both the model's reasoning and how it treats tool evidence.

Many evaluations of tool-augmented agents focus on choosing tools, forming arguments, handling explicit execution errors, or finishing tasks with tool access. These are useful settings, but they miss an important reliability problem. In real data systems, tools can return outputs that look normal but are wrong: a pipeline may use the wrong unit conversion, retrieval may return stale rows, preprocessing may swap column meanings, or user data may include text that looks like metadata. These failures often do not raise errors. The tool call succeeds, and the agent must decide whether to trust the result.

We call this problem \emph{silent tool poisoning}. The tool interface stays the same, and the agent receives a well-formed output. The agent must use context, simple consistency checks, or extra validation to see that the content is unreliable. This matters for data agents because many wrong analytical statements still look plausible. For example, a corrupted mean, a biased retrieval result, or a stale metadata field can be copied into the final answer.

We ask a simple question: if a tool silently returns false evidence, do data agents notice? We introduce ToxicBench, a benchmark that injects controlled silent failures into data-analysis environments while keeping tool calls successful. We evaluate agents and models on two suites: 34 numerical tasks and 24 semantic/schema tasks. We also run a GPT-only cross-agent evaluation on 120 instances and a separate leakage-free 120-instance LangGraph ReAct defense ablation. The numerical suite corrupts aggregates, signs, ratios, and entity--statistic bindings. The semantic/schema suite corrupts treatment/control labels, column meanings, stale data-dictionary entries, and retrieved snippets. We measure not only task success, but also whether agents copy poisoned outputs, flag anomalies, validate independently, and recover the clean answer.

We also study a lightweight protocol, Guarded Verification, to test how extra evidence and evidence-gating policies affect answers. Before using tools, the agent writes generic expectations that do not reveal the poison type or the clean answer. After tool use, the protocol runs an additional validation route before finalizing. On 120 instances, it reduces exposure-conditioned BCR from 0.11 to 0.00 and increases poisoned TSR from 0.82 to 0.93. A compute-matched unguarded second pass reaches BCR 0.01 and poisoned TSR 0.92, which suggests that most gains come from extra evidence and compute; the guard policy removes the remaining blind compliance we observe. Under repeated route poisoning, BCR becomes nonzero and recovery drops. So this is a controlled study of evidence auditing, not a guarantee against compromised sources, shared caches, or routes.

Our contributions are:
\begin{itemize}
    \item We formulate silent tool poisoning as an agent evaluation problem distinct from explicit tool failure and ordinary hallucination.
    \item We introduce ToxicBench, a benchmark for testing blind compliance to poisoned but successful tool outputs in data-analysis agents, with numerical and semantic/schema task families.
    \item We define behavioral metrics that separate clean capability from trust calibration, including blind compliance, anomaly detection, validation, recovery, and poisoned-task degradation.
    \item We evaluate complete framework adapters, showing that high clean-task performance often coexists with blind compliance under silent poisoning.
    \item We evaluate Guarded Verification as a controlled attribution protocol against a matched-compute control and under repeated route poisoning, separating the benefit of extra evidence from the incremental guard policy and identifying where both fail.
\end{itemize}
