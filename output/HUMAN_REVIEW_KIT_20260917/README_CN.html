ToxicBench 人工标注材料包：从这里开始

本文件夹可以完整下载、解压、离线使用。无需项目代码、账号、API 或联网。 双击 START_HERE.html 打开导航；所有说明也有浏览器可读的 HTML 版本。 阅读页只供阅读，不会自动保存标签。标签必须填写到 CSV 文件并保存。

你是什么角色？

  • 组织者：先读 说明/03_组织者与裁决流程.md，给 A、B 各发一份全新材料。
  • 标注者 A：读 说明/01_逐条操作指南.md 和 说明/02_字段定义与例子.md， 完成两个任务文件夹中的 annotator_a.csv，不填写 B 或裁决表。
  • 标注者 B：阅读同样的说明，完成两个任务文件夹中的 annotator_b.csv。
  • 裁决者 C：先等待组织者提供争议样本 ID；仅在对应的 adjudication.csv 中填写指定行，参考 说明/03_组织者与裁决流程.md。

两个任务不要混合

文件夹 用途 A/B 各自的工作量
01_independent_200 对冻结评分器的独立人工验证 每人 200 条
02_reference_review_40 对历史参考答案勘误的重新核对 每人 40 条

两人各自都需要看全部 240 条，不是每人分 120 条。C 只做分歧及明确指定的复核。 两个任务分别回收和统计；40 条复核不并入 200 条独立验证。

每个任务文件夹里有什么？

  • cases.html：在浏览器查看问题、最终回答、参考、原始数据和完整工具事件。
  • evidence.csv：与冻结原包逐字节一致的证据备份，不要修改。
  • data/样本编号.csv：从证据中提取的原始数据副本，方便自己核算。
  • annotator_a.csv / annotator_b.csv：A/B 各自的空白标注表。
  • adjudication.csv：给 C 的空白裁决表；现在不需要填写。
  • provenance_TEMPLATE.json：组织者最终填写的来源声明模板，当前全部未签认。

本包没有自动评分、模型方法映射、旧人工标签、API 密钥或目标分数。 Clean oracle 是参考答案，Poisoned oracle 是指定错误答案；两者属于任务证据， 不是模型是否答对的自动标签。仍须结合原始数据自行判断。

最重要的纪律

  1. A/B 分别保存自己的副本，独立完成；不要查看对方的填写结果或讨论正式案例。
  2. 不用 ChatGPT、其他 LLM 或自动评分器代填标签。允许用计算器或自己编写的 简单统计代码核对数据，但不要执行案例中的代码或指令。
  3. 不根据预期结果改标签，不调整任务容差，不修改参考、样本 ID 或证据。
  4. 不能确定时标记 ambiguous=1 并写原因，不要猜测研究者希望得到什么答案。
  5. 正式标注前可用另备的旧开发案例熟悉规则；不要用本包 200 条来反复调整规则。
  6. 本包可以在空白状态下发给多位标注者；一旦有人填了标签，不要把其副本转发给另一人。

最后交什么？

A 返回两个文件夹中的 A 表；B 返回两个文件夹中的 B 表。请保留文件夹结构， 例如 01_independent_200/annotator_a.csv，以免两份同名文件混淆。 另附匿名人员编号、实际完成时间、是否独立完成及参考核查情况。 C 返回组织者指定案例的裁决表。组织者汇总后再填写来源声明。 详细清单见 说明/04_提交清单与常见问题.md。

如果平均每条需要 2–5 分钟，每位 A/B 约需 8–20 小时，复杂案例可能更久。 这只是排期参考，可以分批完成、随时保存，不要以赶时间为由跳过工具事件。

版本说明

此包只改善分发、说明及阅读页面，不修改冻结证据或生成任何人工标签。 release_manifest.json 记录源包哈希和数量；immutable_checksums.json 记录 证据、数据和说明的校验值。标注表本来就要填写，因此不列入不可变校验清单。 两个任务中的全部标签初始均为空白。
