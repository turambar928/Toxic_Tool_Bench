\section{Conclusion and Limitations}
\label{sec:discussion}

ToxicBench measures how data agents respond when a successful tool call returns wrong evidence. Its paired tasks separate changes to the returned observation from changes to source data. The verification experiments distinguish another attempt at the task from an explicit request to check an earlier answer. Later clean observations are common under one-shot poisoning; repeated poisoning exposes cases in which agents check evidence and still adopt the wrong conclusion, a behavior confirmed on four adjudicated holdout trajectories. Together, the task pairs, trace analysis, and human comparisons provide a common setting for testing how agents select and use evidence.

The benchmark uses small synthetic tables and controlled observation changes; it diagnoses evidence-use failures rather than estimating their deployment frequency. Routes share tables and backends, and repeated poisoning can corrupt the check itself. The revised parser has been development-tested but still needs independent human validation. Reference corrections also require re-review of affected historical labels. Clustered intervals address task dependence, not uncertainty in those labels or variation across repeated API runs. Larger real-data workflows and separate evidence sources remain outside the demonstrated scope.
