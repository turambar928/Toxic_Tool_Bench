\section{Experiments}
\label{sec:experiments}

\subsection{Research Questions}

Our experiments evaluate four questions:
\begin{itemize}
    \item \textbf{RQ1:} How often do data agents blindly comply with silently poisoned tool outputs?
    \item \textbf{RQ2:} Which poisoning operators are most damaging within numerical and semantic/schema tasks?
    \item \textbf{RQ3:} Does stronger clean-task performance imply better trust calibration under poisoning?
    \item \textbf{RQ4:} Can Guarded Verification reduce blind compliance without substantially hurting clean-task performance?
\end{itemize}

\subsection{Experimental Setup}

\paragraph{Tasks.}
We use two scales of task suites. For cross-model experiments, the numerical suite contains 34 tasks over 11 CSV datasets and covers means, totals, growth rates, group rankings, ratios, retention rates, defect rates, and support-queue statistics. The semantic/schema suite contains 24 tasks over 14 CSV datasets and covers treatment--control label flips, schema column swaps, stale metadata in data dictionaries, and biased retrieval evidence. To increase cross-agent coverage, we additionally run a GPT-only expanded evaluation with 60 numerical tasks and 60 semantic/schema tasks. The same 120-task expanded suites are used for the LangGraph ReAct defense ablation. We report numerical and semantic/schema results separately because they stress different trust failures: arithmetic robustness versus evidence binding, schema interpretation, and retrieval grounding.

\paragraph{Agents and models.}
We evaluate complete framework adapters rather than prompt-only profiles. The adapters are LangGraph ReAct, Hugging Face smolagents, PandasAI, DA-Agent, and AutoGen. We run all completed adapters with \texttt{gpt-5.4-mini}. For cross-model experiments, we run LangGraph, smolagents, PandasAI, and AutoGen with \texttt{claude-sonnet-4-6} and \texttt{Qwen3.6-35B-A3B-no-thinking}. DA-Agent is included in the GPT main table but excluded from cross-model tables because the Claude run reached only 5 of 68 clean/poisoned environment instances after more than twenty minutes.

\paragraph{Poisoning boundaries.}
LangGraph, smolagents, and AutoGen are poisoned at a tool-observation boundary. PandasAI is coarser: it runs the full agent and applies poisoning at the chat-result boundary because internal code-execution observations are not exposed through the same protocol. PandasAI BCR therefore measures end-to-end susceptibility to a poisoned final chat result, not fine-grained compliance with an individual internal dataframe observation. These are end-to-end framework measurements rather than pure model-only comparisons.

\paragraph{Analysis.}
For each agent, model, and task family, we report clean TSR, poisoned TSR, $\Delta$TSR, BCR, ADR, VR, and RR where space permits. We also inspect trajectories to identify failure modes such as copying a poisoned value into the final report, rationalizing an inconsistent result, accepting corrupted metadata, or validating but not using the validation result. Section~\ref{sec:qualitative} summarizes representative trajectories from the final rescored runs.

\subsection{Poison-Type Breakdown}

The numerical suite lets us compare poisoning operators across completed model--adapter groups. Table~\ref{tab:poison-type-breakdown} shows that rank swaps are the most likely to induce blind compliance, with average BCR 0.52. Aggregate scaling is also damaging, with average BCR 0.41 and average poisoned TSR 0.43. Sign flips are easier for agents to recover from: average poisoned TSR is 0.90, average BCR is 0.11, and average recovery is 0.28. This pattern suggests that entity binding and plausible aggregate values are more dangerous than sign errors that often contradict visible trends.

\subsection{Guarded Verification Ablation}

We next evaluate whether Guarded Verification can reduce blind compliance for LangGraph ReAct. The guarded adapter first elicits task-specific expectations about columns, labels, entity bindings, and evidence rows, then runs the normal ReAct tool route, and finally performs an independent verification pass before producing the final answer. In our scorer, a validation event only counts toward VR when it is a fresh post-poison tool call or recomputation that is separate from the poisoned observation; restating the primary answer or expressing rhetorical doubt is insufficient. This design targets silent observation poisoning rather than prompt-level instruction following.

Table~\ref{tab:langgraph-guarded} reports the full 120-task ablation across six LangGraph variants. The base adapter has high clean TSR (0.93) but drops to 0.62 poisoned TSR with BCR 0.30. Caution-only prompting reduces BCR but does not remove blind compliance, and expectation-only leaves nearly the same failure pattern as the base route. In contrast, variants that perform independent verification reduce observed BCR to 0.00. The full guard improves poisoned TSR to 0.93 while preserving clean TSR at 0.93; the light guard obtains the same poisoned TSR with a slightly lower clean TSR. Verification-only also performs strongly, indicating that independent evidence gathering is the main active ingredient.

\paragraph{Clean-run false positives and overhead.}
The full guard verifies every task, so clean-run VR should be read as an unnecessary-verification rate rather than as anomaly detection. We estimate harmful false positives by clean TSR regression: on the 120-task ablation, full guard clean TSR is 0.93 versus 0.93 for base LangGraph, so always-on verification does not reduce aggregate clean success in this setting. The cost is concrete: base LangGraph averages 2.04 tool events and 7.92 seconds per task, while full guard averages 4.67 tool events and 22.72 seconds; the median/90th-percentile latency rises from 7.31/10.60 seconds to 21.28/29.51 seconds. Light guard is slightly cheaper at 4.53 tool events and 21.09 seconds on average, with median/90th-percentile latency 20.64/26.33 seconds. Budgeted policies can be less stable, however, because they sometimes spend steps on verification while failing ordinary answer extraction. We log wall-clock time and tool-event counts for every run; the released overhead summaries report these timing proxies, and Appendix~\ref{sec:appendix-guard} now includes a compact latency distribution table. We do not claim provider billing deltas because the API logs do not expose reliable per-call dollar costs across all model gateways.

\paragraph{Second-framework replication.}
To test whether the mitigation is tied to LangGraph, we replicate the core verification variants on AutoGen over the same 120 expanded tasks. The base AutoGen adapter in Table~\ref{tab:gpt-expanded-cross-agent-120} has poisoned TSR 0.65 and BCR 0.20. AutoGen verification-only and guarded variants both reduce BCR to 0.00 and obtain poisoned TSR 0.93, with clean TSR 0.93 and 0.92, respectively. The replication has a similar cost profile: verification-only averages 4.11 tool events and 27.10 seconds, while guarded averages 4.07 tool events and 25.41 seconds, with median/90th-percentile latency 26.01/32.34 seconds and 24.60/29.60 seconds. This result does not make a universal framework-generalization claim, but it shows that the main BCR reduction is reproducible in a second public agent loop. Appendix~\ref{sec:appendix-autogen-replication} reports the suite breakdown and runtime.

\subsection{Supplementary Defense Stress Tests}

We further probe two harder settings: cheaper verification policies and repeated poisoning of verification routes. Table~\ref{tab:defense-stress-main} summarizes a fixed stratified subset covering numerical aggregate/rank/sign/ratio corruptions and semantic label/schema/stale/retrieval corruptions. The abstain policy eliminates blind compliance but loses task success, especially on numerical tasks. Randomized verification is cheaper, but it misses high-risk semantic cases and leaves BCR at 0.30 on the semantic subset. Selective verification performs best among the cheaper policies on the semantic subset, matching the full guard's qualitative behavior on these cases, but still leaves residual BCR on the harder numerical subset.

We also stress the \texttt{poison\_once} assumption by allowing repeated probabilistic poisoning on the semantic subset. With \texttt{--poison-repeat}, increasing the probability that each eligible verification observation is also corrupted reduces recovery: toxic TSR/RR falls from 0.80 at \(p=0\) to 0.10 at \(p=1.0\). BCR remains 0.00 across this stress test because the guard continues to mark the evidence as contested rather than silently adopting the poisoned result. Thus, under stronger adversaries, the guarantee should be interpreted as reducing blind compliance, not guaranteeing recovery when every evidence route can be corrupted.

\subsection{Multi-Table Join Extension}

To move beyond single-table CSV analysis, we add a realistic extension suite with 13 tasks over four joined table pairs. The tasks require notebook-style reasoning: discover the correct table pair, inspect both tables, and compute the answer through an exact join or cross-table validation. The suite is released as \texttt{realistic\_extension\_iclr2027.jsonl} together with the auxiliary tables used by the execution tools.

On this extension, the base LangGraph ReAct adapter obtains clean TSR 1.00 and poisoned TSR 0.23 with BCR 0.77. This shows that silent poisoning remains challenging when tasks move beyond a single flat table and require join-style analysis: the agent can solve the clean join but still adopt a corrupted observation under poisoning. Guarded Verification transfers to this harder execution surface: both full and light guards reach poisoned TSR 1.00 with BCR 0.00. The result supports the same conclusion as the 120-task ablation, with higher latency because each join task needs an additional evidence route.

\subsection{Uncertainty and Experimental Caveats}

We compute nonparametric bootstrap confidence intervals by resampling task IDs with replacement and recomputing clean TSR, poisoned TSR, $\Delta$TSR, BCR, ADR, VR, and RR. The full CI tables are released for the numerical cross-model results, semantic/schema cross-model results, and the expanded guarded LangGraph ablation. The guarded ablation CIs are summarized in Appendix~\ref{sec:appendix-guard}.

The results should be interpreted as end-to-end framework measurements. DA-Agent is excluded from the Claude and Qwen cross-model tables because of runtime, and PandasAI uses a coarser poisoning boundary. These caveats affect fine-grained model comparisons, but not the main finding: successful tool use often coexists with blind compliance under silent observation poisoning, and structured verification can reduce that compliance.
