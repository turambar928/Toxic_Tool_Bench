\section{Conclusion and Limitations}
\label{sec:discussion}

ToxicBench measures how data agents respond when a successful tool call returns wrong evidence. Its paired tasks separate changes to the returned observation from changes to source data. The verification experiments distinguish another attempt at the task from an explicit request to check an earlier answer. Later clean observations are common under one-shot poisoning; repeated poisoning exposes cases in which agents check evidence and still adopt the wrong conclusion, a behavior confirmed on four adjudicated holdout trajectories. Together, the task pairs, trace analysis, and human comparisons provide a common setting for testing how agents select and use evidence.

The core benchmark uses small synthetic tables and controlled observation changes, not deployment-frequency sampling. Six tasks on a larger public observational table show ceiling performance, offering limited transfer evidence rather than method separation. Routes share sources, and repeated poisoning can corrupt checks. Delivery auditing flags historical off-target edits; the repaired injector is conservative but does not certify every semantic binding. Independent human scorer validation and affected-label re-review remain pending. Clustered intervals address task dependence, not label uncertainty or repeated API variation. Production-scale workflows and separate evidence sources remain outside the demonstrated scope.
