\begin{abstract}
Tool-augmented language agents are increasingly used for data analysis, where they query databases, execute code, retrieve documentation, and write reports from tool observations. Most reliability evaluations focus on visible failures such as crashes, timeouts, malformed outputs, or unavailable APIs. We study a less visible failure mode: the tool call succeeds and returns a well-formed, relevant observation, but the content is incorrect.

We introduce ToxicBench, a benchmark for measuring whether data agents blindly comply with such silent tool poisoning. ToxicBench wraps ordinary data-analysis tools with controlled perturbations that preserve normal execution, including corrupted numerical results, swapped labels and schema meanings, stale metadata, and biased retrieval evidence. We evaluate 34 numerical tasks and 24 semantic/schema tasks with full framework adapters for LangGraph, smolagents, PandasAI, DA-Agent, and AutoGen across three model families where practical, and run a larger 120-instance GPT-only evaluation. The results show a consistent gap between tool use and tool trust: agents that solve clean tasks often copy poisoned values or corrupted labels into final answers. Finally, we evaluate Guarded Verification using a leakage-free 120-instance LangGraph ReAct ablation with a matched-compute control. A generic guard reduces exposure-conditioned blind compliance from 0.11 to 0.00 and improves poisoned-task success from 0.82 to 0.93, although an unguarded second pass explains much of the gain. A full repeated-poison stress test further shows that recovery degrades and blind compliance can return when verification observations are also corrupted.
\end{abstract}
