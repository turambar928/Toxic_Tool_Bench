\section{Experiments}
\label{sec:experiments}

\subsection{Research Questions}

Our experiments are organized around four questions:
\begin{itemize}
    \item \textbf{RQ1:} How often do data agents blindly comply with silently poisoned tool outputs?
    \item \textbf{RQ2:} Which poisoning operators are most damaging within numerical and semantic/schema tasks?
    \item \textbf{RQ3:} Does stronger clean-task performance imply better trust calibration under poisoning?
    \item \textbf{RQ4:} Can \methodname{} reduce blind compliance without substantially hurting clean-task performance?
\end{itemize}

\subsection{Agents and Baselines}

We evaluate complete framework adapters rather than only prompt-style profiles. The current suite includes \texttt{data2mcp}'s DataFrame router, DA-Agent, LangGraph ReAct, Hugging Face smolagents, PandasAI, and AutoGen. Each adapter receives the same user query and has access to benchmark-controlled data tools. The clean run receives unmodified observations; the poisoned run receives the same tool interface with selected observations silently perturbed.

\paragraph{Implementation note.}
Most adapters are poisoned at the tool-observation boundary. PandasAI is a coarser integration: it runs the full PandasAI agent and applies poisoning at the chat-result boundary, because its internal code-execution observations are not exposed through the same tool protocol.

\subsection{Task Suite and Models}

The expanded numerical suite contains 34 tasks over 11 CSV datasets. We run all completed adapters with \texttt{gpt-5.4-mini}. We additionally run cross-model experiments with \texttt{claude-sonnet-4-6} and \texttt{Qwen3.6-35B-A3B-no-thinking} for the five adapters that complete at practical speed: LangGraph, smolagents, \texttt{data2mcp}, PandasAI, and AutoGen. DA-Agent completes on \texttt{gpt-5.4-mini}, but the Claude run reached only 5 of 68 clean/poisoned environment instances after more than twenty minutes, so we exclude it from the cross-model table and report it as a scalability limitation.

We have also prepared and run a 24-task semantic/schema suite covering treatment--control label flips, schema column swaps, stale metadata in data dictionaries, and biased retrieval evidence. These tasks are reported separately from the numerical suite because they measure trust in metadata, retrieval evidence, and entity binding rather than arithmetic robustness.

\subsection{Analysis Plan}

We report clean TSR, poisoned TSR, $\Delta$TSR, BCR, ADR, VR, and RR by agent, model, task family, and poisoning type. We also inspect trajectories to identify common failure patterns, such as copying the poisoned value into the final report, rationalizing an impossible result, accepting corrupted metadata, or performing validation but ignoring the validation result.
Section~\ref{sec:qualitative} summarizes representative trajectories from the final rescored expanded runs.

\subsection{Guarded Verification Ablation}

We next evaluate whether a lightweight guarded policy can reduce blind compliance for \texttt{data2mcp}. The guarded adapter first elicits task-specific expectations about columns, labels, entity bindings, and evidence rows, then runs the normal data-analysis route, and finally performs an independent verification pass before producing the final answer. This design targets silent observation poisoning rather than prompt-level instruction following.

Table~\ref{tab:data2mcp-guarded} shows guarded ablations on both the semantic/schema and numerical suites with \texttt{gpt-5.4-mini}. The guard eliminates observed blind compliance in both runs. On semantic/schema tasks, poisoned TSR rises from 0.29 to 0.83, with a clean TSR tradeoff from 0.92 to 0.83. On numerical tasks, both clean and poisoned TSR improve because the verification pass also corrects some ordinary data2mcp tool-use failures. A lower-budget light guard keeps BCR at 0.00 but loses task success; we report it as an appendix tradeoff rather than the main defense result.

\subsection{Cross-Model Results}

Tables~\ref{tab:claude-expanded} and~\ref{tab:qwen-expanded} show the same expanded suite on Claude and Qwen for the five practical-speed adapters. The qualitative pattern persists: poisoned TSR is consistently below clean TSR, and blind compliance remains nonzero even for agents with high clean TSR. The magnitude varies by model and framework. Claude reduces degradation for LangGraph, smolagents, and AutoGen, but PandasAI remains highly vulnerable. Qwen shows strong LangGraph clean performance but large poisoned degradation, and \texttt{data2mcp} has low clean TSR under this model because many runs hit the maximum-turn limit without a final answer.

\paragraph{Poison-type breakdown.}
Across the completed cross-model runs, rank swaps are the most likely to induce blind compliance, with an average BCR of 0.52 across model--adapter groups. Aggregate scaling is also damaging, with average BCR 0.41 and average poisoned TSR 0.43. Sign flips are easier for agents to recover from: average poisoned TSR is 0.90, average BCR is 0.11, and average recovery is 0.28. The full breakdown is stored in \texttt{poison\_type\_summary.csv}.
